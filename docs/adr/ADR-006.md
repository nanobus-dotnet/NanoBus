# ADR-006: Bounded Channels with 100-Message Default Capacity

**Date:** 2026.10.05  
**Status:** Accepted  
**Decider(s):** Wayland Young  
**Affected Components:** `MessageChannelRouter`, `InMemoryTransport`

## Context
The `MessageChannelRouter` creates one bounded channel per message type (in `_typeChannels`). Each channel must decide:  
- **Bounded or unbounded?** (memory safety vs. latency predictability)
- **What capacity?** (trade-off between buffering and backpressure)

Unbounded channels avoid backpressure but risk memory exhaustion. 
Too small bounds cause artificial queuing delays. 
Too large bounds waste memory for low-frequency message types.

## Decision
Use **bounded channels with a default capacity of 100 messages per type**:

```csharp
// In AddInMemoryServiceBus( ) configurable through transport options
var channelManager = new MessageChannelRouter(transportOptions.MaxChannelCapacity);

// In MessageChannelRouter EnqueueMessageAsync( )
Channel.CreateBounded<(IMessage, MessageMethod, MessageContext, CancellationToken)>(
    new BoundedChannelOptions(BoundedChannelCapacity) 
    { 
        FullMode = BoundedChannelFullMode.Wait 
    }));
```

## Rationale
- **Default value:** Sensible capacity (100) but overridable.
- **Memory conservation:** Bounded channels will wait when full (backpressure) and not grow unchecked.

## Consequences
- **Positive:**
  - Memory usage does not grow unchecked.
  - Provides natural backpressure if message producers are fast and consumers are slow.

- **Negative:**
  - Set at the default level, channels can reach capacity and cause queueing delays + message latency. API Consumer can override if necessary.
  - 100 capacity channel size could still waste some memory on low-frequency message types. Minimal impact.


## Alternatives Considered
| Alternative | Why Rejected |
|------------|-------------|
| Unbounded channels | Memory usage can grow unchecked if message producers are fast and consumers slow |
| > 100 channel capacity | Potential for more memory waste |
| < 100 channel capacity | Potential for more queueing delays + message latency |
