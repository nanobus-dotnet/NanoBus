# ADR-003: Notification-Driven Message Delivery Loop With No Polling

**Date:** 2026.10.05  
**Status:** Accepted  
**Decider(s):** Wayland Young  
**Affected Components:** `InMemoryTransport`, `MessageChannelRouter`

## Context
The `InMemoryTransport` must deliver messages to handlers efficiently without polling. 
The system needs to scale to thousands of message types with minimal CPU overhead when idle.

## Decision
Use a **notification channel** (`_channelNotification`) to signal the delivery loop when new messages arrive.
The delivery loop maintains a `Dictionary<string, Task>` of active delivery tasks (one per message type) 
and creates new tasks on-demand when notified.

## Rationale
- **Zero CPU overhead at idle:** No polling; the delivery loop blocks on `WaitToReadAsync`.
- **Scalability:** One task per active message type, not per message.
- **Bounded channels:** Each message type gets a bounded channel (default 100 capacity), preventing unbounded memory growth.
- **Clean shutdown:** The notification channel is completed in `StopAsync`, cleanly signaling the loop to exit.

## Consequences
- **Positive:** 
  - CPU-efficient (async/await, no busy loops)
  - Simple concurrency model (notifications decouple enqueue from delivery)
  - Testable with `TaskCompletionSource`
- **Negative:** 
  - One extra notification write per message batch
  - Complexity in cleanup logic task removal)
- **Neutral:** Notification channel itself is unbounded which is acceptable since the number of message types will be a reasonable, fixed size

## Alternatives Considered
| Alternative | Why Rejected |
|------------|-------------|
| Polling loop (1s interval) | High CPU cost, latency jitter, poor scalability |
| One task per message | Unbounded task creation; difficult to manage lifetime |

## Implementation Notes
- Notify after successful write to message channel in `ChannelManager.EnqueueAsync`.
- Use `Dictionary<string, Task>` with lock-free cleanup via `.ContinueWith`.
- Complete `_channelNotification` before awaiting delivery tasks in `StopAsync`.
